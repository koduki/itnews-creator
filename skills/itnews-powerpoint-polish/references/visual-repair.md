# Native PowerPoint visual repair playbook

## Authentic external evidence
- Prefer factual source images that contribute meaning: a product in actual use, event/incident photo, specific article diagram, measured performance plot, source web-page statement, GitHub changeset, real UI state or relevant original keynote graphic.
- A specific image from credible journalism may be better than a vendor's promotional photo. Keep the source article, photo/diagram credit, publication date and usage terms. Article URLs do not grant download/reproduction rights.
- If evidence lies in an article's wording or visual context, a correctly cropped **real page capture** is useful. If the image itself is the evidence, prefer the actual attributed asset, not an unreadable full-page screen capture.
- When a picture file is actually available and reuse is appropriate, insert it into the slide; check the object was embedded and its focal subject readable at slideshow scale.
- No network/browser screenshot tool? Ask for the actual asset or disclose the image as missing; **do not** fill the slot with stock art or AI-generated lookalikes.

## Shapes and technical diagrams
- Preserve meaning before appearance. Check node labels, arrows, direction, transformation vs communication, protocols and units.
- Use native PowerPoint shapes/connectors for newly authored explanatory diagrams when supported, marking simplified architecture as a conceptual diagram. Keep source/vendor diagrams raster if their appearance is evidence.
- Rebuild an existing visual as editable only with sufficient data; do not falsely imply exact original measurements.

## Charts and tables
- Inspect raw values and measurement conditions, denominators, versions, workloads and axes. For comparisons: equivalent conditions or a prominent caveat.
- Editable native chart when the host permits; otherwise a properly sourced screenshot is acceptable when documentary nature matters.
- If labels cannot be read in projection, split into a summary slide and a full-size evidence detail rather than indefinitely shrinking type.

## Layout and typography
- 16:9; mainly white with red `#C00000` for headlines/topic emphasis; charcoal body text. Aim for body around 20–28 pt when feasible; authentic dense image captions may be smaller but remain legible.
- Fix clipped text, collisions, inconsistent margins, stretched screenshots and tiny source citations. Avoid auto-design changes that replace technical intent with pictograms or decorative imagery.
- Source evidence pages may legitimately be dominated by a single large screenshot with little additional prose; the speaker notes can provide the oral emphasis and provenance.

## Changes that require explicit care
- Removing slides, changing the news lineup or editing a verified numeric claim.
- Replacing a genuine sourced screenshot with a different image.
- Shrinking source content enough to make it unreadable, altering a crop that removes qualifying context or omitting a necessary caveat.
- Overwriting original draft when the user expects a separate polished version. Prefer save-as/copy when supported and especially before structural changes.

## v0.7 order of operations (from real comparison)
1. Inspect the deck's agenda and sequence, make one uninterrupted group per news item; move second-tour market/risk/evidence slides next to their own story.
2. Find exact sources for the most informative missing actual photos and screenshots; do not use a full webpage thumbnail if a relevant credited news image/figure is better. If the feature cannot acquire pixels, document the exact desired asset and leave it pending.
3. Balance each explanation with source-led pages and truly necessary diagrams. Neither maximize the image count nor turn every slide into a card/chart.
4. Only then resolve typography, crop and speaker notes, and run final PowerPoint-native visual QA.
