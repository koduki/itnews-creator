# Repair a Chat-authored Weekly IT News deck (v0.7)

## Work from the actual deck, not from a slide-template ideal
A real **2026-10-25 v0.5 deck** contains 22 slides, 4 embedded image objects, and a repeated three-topic cycle. A **2026-03-15 pre-AI reference** contains 31 slides, 33 embedded image objects and substantive actual-source imagery. These are diagnostic observations, not fixed image quotas or a mandate to mimic the older deck's misaligned typography. Do not distribute third-party images from the samples.

## First: repair story continuity, then finish media
- Inventory slide number → topic → role (cover / agenda / explainer / real evidence / analysis / technical / summary). Flag every **reopened topic** after another topic begins. Group repeated blocks back under their original news item, preserving factual claims and author voice. For the supplied 2026-10-25 draft, suggested starting order is 3–5, 14–15 (Meta); 6–9, 16–17 (PHP); 10–13, 18–21 (GMO), with 1–2 first and 22 optional last. **This is an example repair plan, not an instruction to duplicate that exact deck.** If moving slides is unsupported, give an exact move list; never claim to have reordered them.
- For each topic after its explainer, review gaps for primary/press visual evidence: a genuine event photo, news article figure, visible product/UI state, real bulletin or relevant technical figure. Favor large legible actual images; a URL alone is not an inserted image and an AI-generated picture is not documentary evidence.
- Use the base's source notes/brief. If only an unnamed 'provided research report' is cited, request/locate the exact publisher + URL rather than invent links. When image acquisition is unavailable in PowerPoint, specify what the user can insert and provide verified links only; do not silently fill with stock art.
- Fix the meaning of diagrams, arrow directions, unit labels and truth-status distinctions before spacing or colors. Keep technical comparisons useful and editable; do **not** flatten every table into an image just because the older decks used many captures.
- Inspect visual density *per topic*, not by a hard image-per-slide quota. Some technical subjects are best served by native diagrams; others require multiple real screenshots. Cite photographer/artist, publisher, URL, date, intended quotation context and use rights where supportable.

## Final acceptance
- All topic blocks contiguous, each starts with explanation, original agenda agrees with sections; optional genuinely cross-topic closing slide does not revisit every news item separately.
- Source media requested for final presentation are **actually embedded**, readable and traceable; unresolved gaps explicitly reported and output labeled unfinished where requirements remain unsatisfied.
- Presenter notes tell the presenter **what to point at** and separate source facts from original commentary.
- Final deck keeps Weekly IT News's lively explanation → evidence rhythm, *not* an unending run of polished corporate cards.
- Verify saved PPTX, readable slides at presentation scale, content provenance, and which checks cannot be performed in the current host.
