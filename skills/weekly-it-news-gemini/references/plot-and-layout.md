# 承認型プロットと固定レイアウト契約

プロットには `edition_date`、`status` (`draft` / `approved`)、`slides` 配列を持つ。各ページに `slide_id`、`story_id`、`layout_id`、`title`、`purpose`、`on_slide`、`speaker_notes`、`asset_ids`、`source_urls` を記録。必要画像は具体的な出典URL、どの部分を撮るか、そのページでの目的も持つ。

## 1. 固定8レイアウトの役割

- **COVER**：3月版の赤黒タイトル、青い日付枠、右上の元アバターを維持。日付と予告（今週のトピック見出し）のみ更新。
- **AGENDA**：2ページ目のシンプルな目次。COVERのトピック見出しと順序・文言を一致させる。
- **NEWS_TITLE**：**ニュースごとのタイトルページ**。3枚目の固有レイアウト（青い `NEWS 01` ラベル、右の淡青の大番号、中央にニュース名）をニュース単位の冒頭に一度だけ配置。
- **NEWS**：ニュースの概要、技術的な切り口、現場への影響、総括。
- **SOURCE_IMAGE**：実ニュース記事・報道画面・公式資料を大きく表示（**原則「1ページ1スクショ」**）。
- **TECH_DIAGRAM**：編集可能な説明用模式図（3ブロック＋矢印）。概念の3世代比較やシステム3層構成図に使用。
- **COMPARE**：数値の単位・比較条件・出典を明示した編集可能なネイティブ表。
- **TWO_SOURCES**：実画像・図解2点と対応する個別の出典・説明。

ひとつの `story_id` は連続した一つのブロック。別のニュースを挟んで同じ `story_id` へ戻らない。強制的な固定ページ数・画像数・まとめは不要。

### ニュースの章扉を必須にするプロット規約

`COVER` / `AGENDA` の次からは `NEWS_TITLE` → ニュース説明・画像・図表という1トピック連続ブロック。ニュース番号は01から順番に採番する。Geminiとの編集会議では章扉も含めた**完成スライド枚数**を提示して承認を得る。

`plot.json` の各ニュースの先頭に `layout_id: "NEWS_TITLE"` を明示するのを推奨。旧7レイアウト形式の承認プロットは、同じ `story_id` の先頭へ決定論的に章扉を追加して後方互換を確保する（既存の明示章扉があれば二重挿入しない）。任意のトップレベル `story_titles: {"meta": "Meta Muse、日本上陸！"}` で章題だけを本文の長い見出しと別に指定できる。

8枚テンプレートの物理番号は `COVER=1, AGENDA=2, NEWS_TITLE=3, NEWS=4, SOURCE_IMAGE=5, TECH_DIAGRAM=6, COMPARE=7, TWO_SOURCES=8`。生成器はこの8レイアウトの固定順序に従う。

## 2. 見出し・用語の番組トーン＆マナー

- **日本で馴染みのある直感的な用語を使う**：欧米の抽象的なバズワード（例：「アンビエントAI」等）は避け、聴衆が一瞬で意味を掴める言葉（例：「常駐型AIエージェント」等）に統一する。
- **番組らしいフックのある見出し**：論文や調査報告書のような硬い見出しではなく、何が起きてなぜヤバいのか・面白いのかが伝わる見出しにする。
  - 例1：`Meta Museが日本で解禁！ 常駐型でAIエージェントの戦いは別のステージへ`
  - 例2：`インターネットが壊れた日。首相も宣言したPHP2Shellとは？`
  - 例3：`勝手に証券を売買まで？ GMO/お名前.comデスクトップクラウド侵害`

## 3. 番組ストーリー展開の定石パターン（黄金構成）

トピックの性質に応じて、以下の展開パターンをベースにページ割りを組む：

### パターンA：新技術・新プロダクト潮流（例：常駐型AIエージェント）
1. **導入 (`NEWS`)**：最新ニュース（日本解禁・ランキング1位等）と、従来型（業務・資料作成等）との違い（EC購入・クーポン等の個人利用強化など）を提示。
2. **証拠画面 (`SOURCE_IMAGE`)**：盛り上がりを示す報道記事のスクリーンショット（1ページ1スクショ）。
3. **概念の3分類・世代比較 (`TECH_DIAGRAM`)**：例「Chat型 → AIエージェント（タスク型/Cron） → AIエージェント（常駐型/専用VM）」のように3ブロックで構造差を明確化。
4. **ブームの起点と課題 (`SOURCE_IMAGE`)**：火付け役となったOSS（OpenClaw等）やキープレイヤー（NVIDIA等）の動向スクショと、その革新性および課題（導入難度・セキュリティ・コスト）。
5. **主要プレイヤー比較表 (`COMPARE`)**：各社の商用プロダクトを「名前・発表/利用開始日・価格・特徴」で一覧比較。
6. **勝因と光と影の深掘り (`NEWS`)**：なぜ特定プロダクトが独走しているのか（例：①クーポンのうまさ等の実利、②生産性ではなく個人の便利さに徹したUX、③無料にできる経済圏の強さ）と、攻めすぎたことによる事故リスク。

### パターンB：大規模脆弱性・社会現象（例：PHP2Shell）
1. **事案の全体像 (`NEWS`)**：確認済み事実（兆候からAI実証・事前試行観測・前倒し公開まで）と「予防的停止」の実態。
2. **政治・経営判断と現場の苦労 (`NEWS`)**：首相発信等が持った意味、過去の重大脆弱性（Log4Shell等）での現場の苦労（社内調整の壁）、なぜ今回「メンテナンス停止」という超高ハードルな選択肢が現実に入ったのか、過去と現在の事情の違い（AIによるパッチ差分から数時間での攻撃生成）。
3. **過去事例との比較 (`COMPARE`)**：技術的差異は軽く触れる程度にとどめ、「凶悪さの類似点」と「世間の認知度・見え方の逆転現象」を比較表で対比。
4. **メカニズムと波及図解 (`TWO_SOURCES`)**：発火経路図と社会的停止の構造図。

### パターンC：クラウド・インシデントと信頼境界（例：GMOお名前.com VPS侵害）
1. **事案の事実整理 (`NEWS`)**：公式確認事実（一部VM侵害・全停止・補償・能動的サイバー防御要請）と攻撃者主張（未確定）の厳密な切り分け。
2. **実害・エスカレーションの報道画面 (`SOURCE_IMAGE` × 複数枚)**：「1ページ1スクショ」で直接的な金銭被害の報道や政府への緊急要請記事を提示。
3. **システム構成と侵害範囲の図解 (`TECH_DIAGRAM`)**：対象クラウドがざっくりどういう構成（例：①管理プレーン/AD層 → ②顧客ゲストVM層 → ③外部口座・手元PC層）になっていて、どこが乗っ取られ何ができるようになったのかを報道ベースで図解。
4. **波及先（外部事業者）の対応理由図解 (`TECH_DIAGRAM`)**：なぜ直接破られていない外部事業者（OANDA証券等）まで緊急対応が必要だったのか（保存認証情報の悪用＋パスワード変更後も既存セッションが維持される仕様上の罠など）を構成図で解説。
5. **信頼境界と逆窓リスク (`TWO_SOURCES` / `SOURCE_IMAGE`)**：RDPドライブリダイレクト（`\\tsclient\C`）の成立条件や、他領域（米大手銀のAIエージェント制限スクショ等）との共通性。
6. **AI時代のセキュリティ総括 (`NEWS`)**：新しいAI防御ツールを入れる話ではなく、「①緊急パッチとメンテ停止の事業承認体制」「②定期的な最新パッチ適用」「③侵入されても終わりにならない設計（権限分離・ACL・Egress制御）」「④当たり前のことを、当たり前に、今まで以上に速やかにやる」で締める。

## 4. テンプレートPPTX生成時の技術仕様（python-pptx 座標・フォント実測値）

テンプレート（`weekly-it-news-design-template.pptx`、13.333" × 7.500"）から生成する際は、以下の実測パラメータを守ることで文字重なり・折り返し・文字化けを防止する：

1. **日本語フォント（豆腐化防止）**：
   - すべての `<a:rPr>` および `<a:defRPr>` に `<a:latin typeface="Yu Gothic"/>（またはテンプレート標準の `Meiryo UI`）` だけでなく **必ず `<a:ea typeface="Yu Gothic"/>` と `<a:cs typeface="Yu Gothic"/>` を明示的に付与**する（LibreOfficeでのPDF/PNG変換時の文字化けを完全に防ぐため）。
2. **表紙（Slide 1 / `COVER`）の日付枠調整**：
   - 月（`Rectangle 1`）：`left=2.28"`, `top=2.92"`, `width=2.12"`、右揃え（`algn="r"`）、**56pt Bold**（2桁の「10月」等でも枠内に綺麗に収まる）。
   - 日（`TextBox 4`）：`left=0.75"`, `top=3.62"`, `width=2.30"`、左揃え（`algn="l"`）、**126pt**（「10月」と重ならない）。
   - トピック枠（`TextBox 13`）：`left=4.74"`, `top=3.00"`, `width=8.10"`, `height=3.60"`、**21pt Bold**、`space_after=14pt`。
3. **本文スライドタイトル（`TextBox 1`）の1行収まり保証**：
   - 赤ライン（`Rectangle 2`: `y=1.12"`）に絶対にかからないよう、`TextBox 1` は `top=0.32"`, `width=12.15"`, `height=0.72"` とし、タイトル文字数に応じてフォントサイズを動的スケールする：
     - 45文字以上：**18.0pt**
     - 39〜44文字：**19.5pt**
     - 33〜38文字：**22.0pt**
     - 32文字以下：**25.0pt**
4. **比較表（`COMPARE`）のセルサイズ**：
   - テーブル領域は `left=0.75"`, `top=1.90"`, `height=4.30"`。
   - 4〜5行の表はヘッダー **15pt Bold**・本文 **13pt**、6〜7行の表（6製品比較など）はヘッダー **14pt Bold**・本文 **12.5pt** に設定し、セル内テキストの溢れを防ぐ。
5. **模式図（`TECH_DIAGRAM`）の3ブロック拡張**：
   - 3つのグレーボックス（`Rectangle 5, 7, 9`）は `x=[0.75", 4.95", 9.15"]`, `top=2.15"`, `width=3.40"`, `height=3.95"` に拡張し、見出し（17.5pt 赤Bold）＋箇条書き本文（14.5pt）が余裕をもって収まるようにする。矢印（`TextBox 11, 12`）は `x=[4.22", 8.42"]`, `top=3.80"` に配置する。

### NEWS_TITLE（新3枚目）実測

- `News Label`：x=1.00, y=2.50, w=7.00, h=0.40。青の `NEWS NN`、18pt Arial Bold。
- `News Title`：x=1.00, y=3.10, w=11.33, h=1.50。濃紺のニュース名、概ね28〜48ptで長さ調整。**短い番組見出し**を推奨。
- `Big Number`：x=8.00, y=3.80, w=5.00, h=3.30。薄い水色の大番号、200pt。
- `Vertical Bar` / `Accent Bar` の位置、背景色、固有の青系配色は維持。本文の赤ライン・赤文字ルールを章扉へ上書きしない。
