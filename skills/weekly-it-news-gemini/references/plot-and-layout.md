# プロットとテンプレートの境界

## 不変条件

**デザインの唯一の正本は実体検証済みの8枚のPPTXテンプレート。** スキルは各ページの情報と用途だけを規定し、RGB値、フォント、座標、余白、線や塗り、表のセル装飾を再定義しない。COVERのみ元の赤黒の表紙を用い、**AGENDA以降はすべて青基調**のテンプレート書式を継承する。テンプレート固有のアクセント色も勝手に塗り替えない。

- レイアウト選択後は、選んだ見本スライドのネイティブ図形・表・段落・テーマの書式を使い、テキストと証拠画像の実体を差し替える。
- 内容が溢れるときは、見出しの最小限の縮小、図解の分割、プロット再編集で対応する。旧版のデザイン値を流用せず、全面的な再レイアウトや汎用カード化はしない。
- テンプレートを変更する場合は、テンプレート本体、SHA-256マニフェスト、生成器、テストを同じ更新として扱う。
- 書体の欠落を補う場合も、既存書式を壊さない。全ページの視覚QAは必須。

## レイアウトと用途（テンプレートの順序）

| ID | 番号 | 用途 |
| --- | ---: | --- |
| `COVER` | 1 | 表紙・発行日・予告 |
| `AGENDA` | 2 | 番組のニュース一覧 |
| `NEWS_TITLE` | 3 | 各ニュース冒頭の章扉 |
| `NEWS` | 4 | ニュースの説明と評価 |
| `SOURCE_IMAGE` | 5 | 1ページにつき原則1点の実資料 |
| `TECH_DIAGRAM` | 6 | 編集可能な技術図 |
| `COMPARE` | 7 | 出典と条件付き比較表 |
| `TWO_SOURCES` | 8 | 2点の実資料の比較 |

`NEWS_TITLE` は各ニュースブロックの先頭に1枚だけ。プロットで明示済みなら保持し、未記載なら `build_pptx.py` が追加する。自動追加分も含めた完成枚数を承認時に提示する。

## 承認済みプロットの情報契約

`plot.json` は `edition_date`、`status: "approved"`、`slides[]` を持つ。各スライドには `slide_id`、`story_id`、`layout_id`、`title`、`purpose`、`on_slide`、`speaker_notes`、`asset_ids`、`source_urls` を記載する。各 `story_id` のスライドを連続させ、未承認の追加・差し替えをしない。`story_titles` は章扉専用の短いタイトル指定に使える。

構成は技術的な面白さに応じて変える（発表画像 → 技術構造 → 比較 → 考察など）。全ニュースを均等なダイジェストにしない。内容やニュースの真偽はプロットの承認とは別に出典で確認する。

## 生成後の判定

- 生成器は本文のネイティブ形状で、元テンプレートに存在しない色指定や重要な見出しの色変更を検出して失敗させる。検査結果は `template_style_audit` として `qa/preflight.json` に残す。
- 色検査PASSは、読みやすさ・位置・画像の正しさを意味しない。PDF/PNG全ページを目視点検する。
- 検証不能なら完成品を出さずに原因を報告する。手作業の塗り替えで監査を回避しない。
