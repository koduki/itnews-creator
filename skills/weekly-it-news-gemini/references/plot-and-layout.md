# プロット／レイアウト契約（テンプレート優先）

## デザインの正本

**唯一の視覚仕様は `assets/templates/weekly-it-news-design-template.pptx` です。**
色、書体、図形、罫線、余白、タイトル位置、背景、テーブル見出しはPowerPoint原本の値を引き継ぎます。Markdownの指示、PythonのRGB定数、過去バージョンの数値座標よりテンプレートが優先です。

- `COVER`: 表紙のネイティブな題字、日付、アバター、予告。
- `AGENDA`: 今週のトピック一覧。
- `NEWS_TITLE`: 各ニュースの章扉。青のNEWS番号、濃紺の見出し、淡い大番号など**テンプレート自身のスタイルを保持**。
- `NEWS`: ニュース解説。
- `SOURCE_IMAGE`: 実資料1点とポイント・出典（原則**1ページ1スクショ**）。
- `TECH_DIAGRAM`: ネイティブ図形3ブロックの構造説明。
- `COMPARE`: 編集可能なPowerPoint表。**新しい表のセル書式はテンプレートの見本セルを複製**。
- `TWO_SOURCES`: 実画像・説明文2組の比較。

上記の並びはテンプレート内の8つの例示スライドに対応します。テンプレートの内容はサンプルであり、サンプル内のニュース名・数字・文面を新しい号へコピーしてはいけません。

## プロット

`edition_date`、`status` (draft/approved)、`slides[]` を使用。各ページに `slide_id`、`story_id`、`layout_id`、`title`、`purpose`、`on_slide`、`speaker_notes`、`asset_ids`、必要なら `source_urls` を持たせます。

- 同一ニュースのページは連続させ、異なるニュースを挟んで戻らない。
- `COVER` と `AGENDA` の後、各ニュースの先頭に `NEWS_TITLE` を1枚配置。明示プロットがなければ生成器が決定論的に自動追加し、重複は作らない。章扉を含む**出力枚数**を承認前に提示する。
- `story_titles` で本文の長い説明見出しとは別の短い章扉タイトルを指定してよい。
- 既存プロットの`on_slide`はスライド内容、`speaker_notes`は口頭説明。タイトル位置・色・罫線をプロットから再定義しない。
- 画像の出典とファイル実体の両方を検証し、取得不能なら完成扱いにしない。

## 編集パターンはあくまで選択肢

新製品なら「導入→実資料→構造→比較→評価」、重大脆弱性なら「事実→社会・技術的影響→過去事例比較」、侵害なら「事実と攻撃者主張の区別→証拠→信頼境界→対策」などを候補にできます。**必須のページ構成や固定ニュース本数ではありません。** キュレーションは毎回発表者と相談して決めます。

## 生成・視覚QA

- `scripts/build_pptx.py` は元のスライドを複製し、既存段落の書式と図形色を維持したままテキスト／画像を流し込みます。長文対応のフォントサイズやテキスト枠の高さの調整は可能ですが、デザイン色を再指定しません。
- 本文見出しの色はテンプレートで青、表紙の題字は別配色です。**本文を旧版の赤いスタイルに戻してはいけません。**
- 日本語描画には不足している `<a:ea>` のみ補い、元の `<a:latin>`、既存配色／フォントを上書きしません。
- 生成後、LibreOffice等で**全ページを表示**し、重なり・見出し折り返し・色違い・表・画像の可読性を確認。テンプレートと出力を構造比較し、Python検査だけで「視覚QA合格」を主張しません。
