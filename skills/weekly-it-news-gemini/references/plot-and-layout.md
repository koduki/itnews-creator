# 承認型プロットと固定テンプレート契約

## 正本・優先順位

**デザインの唯一の正本は、取得・SHA-256検証済みの `weekly-it-news-design-template.pptx`。** この文書は用途と情報構造を定義するだけで、色・線・マージン・図形の座標・フォントなどを上書きするデザイン仕様書ではない。

- **COVERだけ** 元の赤黒の「Weekly IT News！」、青い日付枠、右上アバターを維持する。
- **AGENDA以降はすべて青基調**。本文タイトル・比較表・ネイティブ図形は元のテンプレートの青／濃紺／淡青を保持する。区切り線はテンプレート固有の黄／金色アクセントも含めて変更しない。本文を赤い見出しにしない。
- 背景、図形の塗り・線、段落スタイル、テーマカラー、行間、位置、寸法、既存表のセル装飾はテンプレートから継承する。新規スライドの汎用デザイン、独自のブランドパレット、マスター上書きは禁止。
- レイアウトや色の修正が必要ならテンプレート自体を編集し、新しいテンプレートハッシュに合わせて生成器とテストを更新する。プロンプトで「赤を青に変えて」と後から塗り直す運用にしない。
- 必要な動的調整は見出しの文字数に応じた最小限の縮小、テンプレートの枠内での画像アスペクト比調整、表の行列追加／図解内のテキスト枠拡張のみ。**テンプレートの実図形を基準**にする。無理に詰めず、密な資料は人とプロットを再調整する。
- CJK豆腐防止は既存Latin/CSフォントを変更せず、欠落している東アジアフォント（`a:ea`）だけを補う。LibreOfficeの表示品質とPowerPoint表示は別々に確認する。

## レイアウトID（テンプレートのスライド順）

| ID | 番号 | 意味 |
| --- | ---: | --- |
| `COVER` | 1 | 今週のタイトル・日付・予告 |
| `AGENDA` | 2 | 週のニュース一覧 |
| `NEWS_TITLE` | 3 | 各ニュース冒頭の章扉（青い `NEWS NN`、濃紺タイトル、淡青の番号） |
| `NEWS` | 4 | ニュース説明、裏付けと発表者の評価 |
| `SOURCE_IMAGE` | 5 | 本物のニュース画像／記事画面、原則1枚ずつ |
| `TECH_DIAGRAM` | 6 | 編集可能な3ブロック構成図 |
| `COMPARE` | 7 | 出典・条件付きの編集可能な比較表 |
| `TWO_SOURCES` | 8 | 2点の資料を個別に説明する比較 |

**章扉はニュースブロックごとに1枚**。プロットに `NEWS_TITLE` があればそのまま使用し、なければ`build_pptx.py`が冒頭に自動挿入する。二重に追加しない。`story_titles` で章扉用の短い見出しを指定できる。完成ページ数は自動追加分を含めて承認時に予告する。

## ページ単位プロット

`edition_date`、`status` (`draft` / `approved`)、`slides[]` を持つ。各スライドは `slide_id`、`story_id`、`layout_id`、`title`、`purpose`、`on_slide`、`speaker_notes`、`asset_ids`、検証済み `source_urls` を記録する。**承認前にはPPTXを生成しない**。ニュースごとの同一 `story_id` は連続させ、別ニュースのあとに再登場させない（承認済みの横断比較は例外）。表紙・目次・章扉と実資料を、発表の話の流れに沿って組み立てる。

### ニュースの展開パターン（義務ではない）

- **新技術・製品潮流**：何が変わったか → 実際の発表画像 → 技術構造 → 比較表 → 勝因・リスク。
- **重大脆弱性**：確認済み事実 → 技術上の発火条件 → 運用・経営判断 → 過去事例との比較 → 現場への示唆。
- **クラウド侵害**：公表事実と攻撃者主張の区別 → 実報道画像 → 信頼境界と侵害経路 → 波及先の影響 → 実施すべき対策。

ニュースを総花的に均等配分せず、発表者と技術的な面白さ・見せたいものを対話で決める。タイトルはレポート調より、過度に煽らない番組調。 unfamiliar な用語は意味が通る日本語にする。**内容例は最新事実ではないのでニュース選定時に独立して検証する。**

## 生成後の確認

`python-pptx` による変換後は元テンプレートとの比較で、**COVER以外の文字・表・図・矢印が赤へ置き換わっていないこと**、テーマカラー・ネイティブ図形・NEWS_TITLEが保持されていることを検査。PDF/PNG全ページ描画で文字重なり・スクショ遮蔽・読みやすさを確認し、失敗はGeminiへ差し戻す。`--strict-assets`の検査は出典・画像の内容そのものを自動認識できないので、実画像の目視検品が必要。
